# Review guide — where human attention pays off

Audience: humans. The agent entry point is [`../AGENTS.md`](../AGENTS.md); the
spec is [`spec.md`](./spec.md), the loop vocabulary is
[`glossary.md`](./glossary.md), and the benchmark's honest weak spots are in
[`../benchmark/README.md`](../benchmark/README.md) §"What we know, and what we
don't" — read that before treating any series number as a stable result.

This ranks the repo by blast radius. An error in Tier 1 invalidates every number
the benchmark reports, so those files deserve a slow, adversarial read; the
goal is catching wrong decisions, wrong claims, and load-bearing mistakes, not
typos.

## Tier 1 — load-bearing; review before trusting a result

- **`src/loop.ts`** — the experiment itself: Run/Edit/Verification semantics,
  the retry, continuation, and no-progress asks, the termination matrix, and
  every model-facing prompt string (`buildContextYaml`, `buildSystemPrompt`,
  `buildUserPrompt`, `buildEditPrompt`, `buildTargetsEditPrompt`,
  `buildCreatePrompt`, `buildRetryPrompt`, `buildContinuationPrompt`, the
  selection variants, the summary). **A change to the model-facing prompt text
  is a change to the experiment**: earlier ledger rows stop being comparable
  until re-measured. Check the caps too (`MAX_EDIT_EXCHANGES`,
  `MAX_RUN_ITERATIONS`, `MAX_STALLED_ROUNDS`, `DEFAULT_TOKEN_BUDGET`).
- **The edit protocol + syntax gate** — `src/loop.ts` payload checks and the
  gate ("nothing is written" on rejection), `src/matcher.ts`
  (`findMatcher` / `applyMatcherSplice`: exactly-one structural match), and
  `src/editor.ts` (`applyEdits` + `oxfmt`). A gate hole silently admits broken
  edits; a guard change moves rejection storms and therefore USD.
- **The judge** — `benchmark/run.ts` `judgeWorkspace`: `tsc --noEmit`,
  `bun test`, and byte-equality of the fixture's `src/*.test.ts` and
  `tsconfig.json`. A judge bug moves every USD number; #68 tracks pinning
  verdicts with a golden corpus.
- **Pricing and aggregation** — `benchmark/run.ts` (`aggregateRuns`, `ok`,
  `costPerSuccess`) with the rate table in `src/benchmark-pricing.ts`. Check
  the denominator rule against "Evidence and provenance" in
  [`../benchmark/README.md`](../benchmark/README.md).
- **Replay format** — `src/replay-format.ts` + `src/replay-runner.ts`: recorded
  bundles (`typescript-coder-replay@1`) replayed with no network calls, record
  by record. A format change without a version bump makes old bundles
  misleading.

## Tier 2 — high-value, but more mechanical

- **Acceptance scenarios** — `acceptance/scenarios.ts` + `acceptance/run.ts`
  (default: fix-answer, keep-progress-retry, persistent-failure,
  context-correctness, check-test-propagation; `self-host` runs under `--all`,
  `live-fix-answer` under `--live`). These are the loop's scripted
  end-to-end contract.
- **Failure-artifact writer** — `src/failure-artifact.ts`: the rendered
  termination diagnostics a storm investigation reads. Keep the pinned target
  and staged diagnostics intact.
- **Frozen fixture text** — `TASK_ISSUES` in `benchmark/run.ts` and
  `benchmark/fixtures/<task>/`. These bytes are what the experiment measures;
  editing them invalidates earlier rows (the provenance rule above).

## Tier 3 — derived or generated; skim, do not line-review

- **Reports** — `benchmark/results/<date>.{json,md}`, generated by `run.ts`.
  Read for claims, not style.
- **Ledger rows** — `benchmark/results/consumption.md`: hand-copied from result
  JSONs; #66 tracks the zero-API check that verifies each row against its
  source.
- **`tmp/`** — scratch workspaces, kept matrices, replay bundles: gitignored
  evidence, not source.

## Suggested review order

1. `benchmark/README.md` — "What we know, and what we don't" and "Evidence and
   provenance" first; then the ledger row a decision cites.
2. `benchmark/run.ts` — judge, then aggregation/pricing.
3. `src/loop.ts` alongside `docs/spec.md` §6 and `docs/glossary.md`.
4. The edit protocol: `src/loop.ts` gate → `src/matcher.ts` → `src/editor.ts`.
5. `src/replay-format.ts` + `src/replay-runner.ts`, then the acceptance suite.

## Gaps a reviewer should not assume are covered

The weak-spot register is [`../benchmark/README.md`](../benchmark/README.md)
§"What we know, and what we don't": n = 3, one model, three frozen fixtures, a
coarse final-state judge, prompt text already tuned once against the fixtures,
and the tracked residual (#65) that re-measures on future
matrices.
