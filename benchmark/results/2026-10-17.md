## Token accounting

ts: OpenAI-compatible `usage` from the provider, summed over every chat request
(input/prompt, output/completion, total; cache and reasoning counters are kept per
record). Cost is recorded verbatim but not compared.

opencode: usage read from `opencode session export` (`info.tokens`), falling back to
`opencode stats --json`; input/output come from the reported session usage and total
is derived from input + output + reasoning when the export reports none. Cost is
recorded verbatim but not compared.

Step counts: ts steps count the loop's replacement attempts (each attempt is one
verify-checked replacement; selection calls are not counted); opencode steps count
assistant messages in the session export. Step counts, cache counters, and reasoning
tokens are not directly comparable across sides and are reported for transparency
only.

Both failures are model-side outcomes, not infrastructure errors:

- Each run consumed exactly 3 loop attempts and exited by exhausting retries
  (`ok:false`, no exception). The split between selection retries and replacement
  attempts is not retained: per-attempt diagnostics live in `side.log` inside the
  run workspace, which the harness removes unless `--keep` is passed.
- A failed replacement attempt is rolled back by design (for create/append targets
  the uncommitted file is removed), so the judged workspace is the pristine
  fixture — the judge output above (TS18003 / missing `./lisp`) describes that
  rolled-back state, not the attempt content.
- Token usage in these runs is dominated by reasoning: `minilisp ts rep1` 87,918 of
  150,816 and `rep3` 64,439 of 123,972 reasoning tokens, versus 73,292 total for
  the passing `minilisp ts rep2`.
- No reruns: the rerun rule covers infrastructure failures only, and none occurred
